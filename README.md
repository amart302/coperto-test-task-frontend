# Coperto Stop List - frontend

Клиентская часть экрана управления стоп-листом смены ресторана. Сотрудник видит справочник блюд, временно снимает позиции с продажи, отслеживает время до автоматического возврата и может досрочно вернуть блюдо в меню.

## Возможности

- справочник из 12 блюд со статусами «В продаже» и «В стопе»;
- фильтрация меню и активного стоп-листа по категориям;
- постановка блюда в стоп с причиной и длительностью;
- клиентская и серверная валидация без `alert`;
- живой обратный отсчёт на основе `expiresAt`;
- автоматическое удаление истёкших записей без перезагрузки;
- досрочный возврат блюда в продажу;
- состояния загрузки, ошибки, повтора запроса и пустого списка;
- адаптивная вёрстка для мобильных и десктопных экранов.

## Стек

- React 19 и TypeScript;
- Vite;
- TanStack Query;
- React Hook Form;
- Zod;
- Vitest и Testing Library;
- нативный CSS.

## Требования

- Node.js 20.19+;
- npm;
- запущенный Coperto Stop List API.

По умолчанию клиент ожидает API по адресу `http://localhost:3001`.

## Локальный запуск

1. Установить зависимости:

```bash
npm install
```

2. Создать локальный файл окружения:

```bash
cp .env.example .env
```

3. При необходимости изменить адрес API:

```env
VITE_API_URL=http://localhost:3001
```

4. Запустить бэкенд на порту `3001`, затем запустить клиент:

```bash
npm run dev
```

Vite выведет локальный адрес приложения, обычно `http://localhost:5173`.

## Используемые эндпоинты

| Метод | URL | Назначение |
| --- | --- | --- |
| `GET` | `/api/dishes` | Получить справочник блюд |
| `GET` | `/api/stop-list` | Получить активный стоп-лист |
| `GET` | `/api/stop-list?category=Кухня` | Отфильтровать стоп-лист по категории |
| `POST` | `/api/stop-list` | Поставить блюдо в стоп |
| `PATCH` | `/api/stop-list/:id/return` | Досрочно вернуть блюдо в продажу |

Пример запроса постановки в стоп:

```json
{
  "dishId": "borsch",
  "reason": "Закончилась свёкла",
  "durationMinutes": 60
}
```

Успешные ответы имеют обёртку:

```json
{
  "success": true,
  "data": {}
}
```

Ошибки API разбираются в едином формате:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": {
      "reason": ["reason must contain at least 5 characters"]
    }
  }
}
```

## Архитектурные решения

Для одного экрана выбрана простая слоистая структура без полного FSD, чтобы границы оставались понятными без лишних абстракций. Работа с HTTP вынесена из компонентов в отдельный API-слой, а серверное состояние управляется через TanStack Query. Правила формы описаны схемой Zod и подключены к React Hook Form; сервер при этом остаётся источником истины и повторно проверяет входные данные. Обратный отсчёт вычисляется из абсолютного `expiresAt`, поэтому он не накапливает погрешность и корректно переживает переключение вкладки.
